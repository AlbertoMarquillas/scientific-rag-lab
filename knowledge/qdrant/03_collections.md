# Collections

---

# What is a Collection?

In Qdrant, a collection is the main organizational structure used to store:

* vectors
* metadata
* payloads
* searchable points

Conceptually, a collection is similar to:

* a table in SQL
* an index in search systems
* a dataset container

Collections organize semantically related data.

---

# Core Idea

A collection groups:

```text
vectors of the same type
```

inside the same retrieval space.

Example:

```text
paper embeddings
```

should usually not mix with:

```text
image embeddings
```

unless intentionally designed.

---

# Why Collections Exist

Collections provide:

* organization
* isolation
* indexing configuration
* search boundaries
* scalability management
* retrieval structure

They are foundational in vector database architecture.

---

# Conceptual Example

Possible collections:

```text
papers
experiments
plots
scientific_notes
agent_memory
```

Each collection stores different semantic objects.

---

# Why Separation Matters

Different data types may require:

* different embeddings
* different dimensions
* different retrieval strategies
* different metadata
* different similarity metrics

Collections isolate these configurations.

---

# Example Problem

Suppose:

```text
text embeddings = 1536 dimensions
image embeddings = 768 dimensions
```

These vectors cannot safely coexist inside the same collection.

Collections enforce vector consistency.

---

# Collection Structure

A collection usually contains:

* points
* vectors
* payloads
* indexes
* metadata schemas

The collection defines the retrieval environment.

---

# What is a Point?

A point is an individual stored object.

A point usually contains:

```text
ID
+
vector
+
payload metadata
```

Collections contain many points.

---

# Example Scientific Point

Conceptually:

```text
Point:
- run_id
- embedding vector
- experiment summary
- turbulence metrics
- metadata
```

Many such points may exist in a collection.

---

# Collections Define Search Space

Similarity search occurs:

```text
inside a collection
```

Example:

```text
query vector
      ↓
search experiment collection
      ↓
retrieve similar experiments
```

Collections define retrieval boundaries.

---

# Why Search Isolation Matters

Suppose:

```text
scientific papers
```

and:

```text
random conversation memory
```

share the same collection.

Semantic retrieval may become noisy.

Collection separation improves retrieval quality.

---

# Collections and Embedding Models

Collections are usually tied to:

```text
one embedding space
```

because embeddings generated by different models may not be geometrically compatible.

---

# Example Embedding Incompatibility

Suppose:

```text
Model A → 1536 dimensions
Model B → 768 dimensions
```

Even if dimensions match, semantic geometry may differ.

Mixing incompatible embeddings may damage retrieval quality.

---

# Collection Configuration

Collections usually define:

* vector dimensions
* similarity metric
* indexing settings
* payload indexing
* replication settings

These configurations affect retrieval behavior.

---

# Similarity Metrics

Collections may use:

* cosine similarity
* dot product
* Euclidean distance

Metric selection influences retrieval quality.

---

# Why Metric Choice Matters

Different embedding models behave differently.

Some embeddings are optimized for:

* cosine similarity
* dot product
* normalized vectors

Collection configuration should match embedding behavior.

---

# Collection Indexing

Collections internally maintain:

```text
vector indexes
```

for efficient nearest-neighbor retrieval.

Indexes accelerate similarity search.

---

# ANN Search Inside Collections

Collections often use:

```text
Approximate Nearest Neighbor (ANN)
```

search structures.

Reason:

exact search over millions of vectors becomes expensive.

ANN enables scalable retrieval.

---

# Payloads in Collections

Collections store payload metadata alongside vectors.

Examples:

```text
run_id
experiment_date
heater_voltage
paper_title
module_name
```

Payloads enable filtering.

---

# Metadata Filtering

Collections support:

```text
semantic retrieval
+
structured filtering
```

Example:

```text
find similar experiments
WHERE scintillation_index > threshold
```

This hybrid capability is extremely powerful.

---

# Collection Granularity

Important design question:

```text
how many collections should exist?
```

This depends on:

* data type
* embedding model
* retrieval goals
* scalability
* isolation needs

Collection architecture is an important design decision.

---

# One Large Collection

Advantages:

* simpler infrastructure
* unified retrieval
* easier cross-domain search

Disadvantages:

* noisier retrieval
* mixed semantics
* weaker isolation
* harder tuning

---

# Multiple Specialized Collections

Advantages:

* cleaner retrieval spaces
* specialized embeddings
* isolated indexing
* better filtering
* easier optimization

Disadvantages:

* more infrastructure complexity
* harder cross-collection search

---

# Collection Design Tradeoffs

Collection design balances:

```text
simplicity
vs
retrieval specialization
```

Production systems often evolve collection architecture over time.

---

# Collection Lifecycle

Collections may be:

* created
* updated
* reindexed
* migrated
* deleted
* versioned

Production retrieval systems continuously evolve.

---

# Reindexing Collections

Sometimes collections require rebuilding.

Reasons:

* new embedding model
* new chunking strategy
* metadata improvements
* retrieval optimization

This may require:

```text
re-ingestion workflows
```

---

# Collection Versioning

Production systems may maintain:

```text
multiple collection versions
```

Example:

```text
papers_v1
papers_v2
```

Useful for:

* migrations
* A/B testing
* rollback
* retrieval evaluation

---

# Multi-Tenant Collections

Some systems isolate users using:

* separate collections
* payload filtering
* namespaces

Important for:

* SaaS systems
* enterprise systems
* collaborative research

---

# Collection Scaling

Large systems may contain:

* millions of vectors
* billions of embeddings
* multimodal datasets

Collections must scale efficiently.

---

# Collection Sharding

Large collections may be distributed across:

```text
multiple machines
```

This is called:

```text
sharding
```

Important for scalability.

---

# Collection Replication

Production systems may replicate collections for:

* reliability
* fault tolerance
* high availability

Replication improves resilience.

Retrieval occurs within these collections.
