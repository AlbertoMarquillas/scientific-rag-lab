# Qdrant Overview

---

# What is Qdrant?

Qdrant is a vector database designed for:

* semantic search
* similarity search
* embeddings storage
* AI retrieval systems
* RAG architectures
* recommendation systems
* multimodal retrieval

Qdrant specializes in searching over:

```text
high-dimensional vectors
```

which are usually generated by AI embedding models.

---

# Core Idea

Traditional databases search using:

```text
exact matches
keywords
structured queries
```

Qdrant searches using:

```text
semantic similarity
```

Meaning:

```text
retrieve information with similar meaning
```

instead of exact textual overlap.

---

# Why Vector Databases Exist

LLMs and embedding models transform data into:

```text
vectors
```

Vectors represent semantic meaning numerically.

Traditional SQL databases are not optimized for:

* nearest-neighbor search
* vector similarity
* embedding retrieval
* high-dimensional indexing

Vector databases were created specifically for these tasks.

---

# Traditional Search vs Semantic Search

Traditional search:

```text
keyword matching
```

Example:

```text
"optical turbulence"
```

retrieves documents containing those exact words.

Semantic search:

```text
meaning-based retrieval
```

can retrieve:

* atmospheric distortion
* beam propagation instability
* scintillation effects

Even if exact words differ.

# Embeddings and Qdrant

Qdrant itself does not create embeddings.

Embedding models generate vectors.

Example:

```text
text
      ↓
embedding model
      ↓
vector
      ↓
Qdrant
```

Qdrant stores and retrieves these vectors efficiently.

---

# Similarity Search

Core retrieval operation:

```text
find vectors similar to query vector
```

Example:

```text
user query
      ↓
query embedding
      ↓
Qdrant similarity search
      ↓
retrieve relevant chunks
```

This powers semantic retrieval.

---

# Why Similarity Search is Powerful

Similarity search enables:

* contextual retrieval

This is one of the foundations of modern RAG systems.

# Collections

Qdrant organizes data into:

```text

```

Conceptually similar to:

---

# Points

Each stored item is called a:

```text
point
```

A point usually contains:

* vector
* ID
* payload metadata

Example:

```text
experiment_summary
+
embedding vector
+
metadata
```

---

# Payloads

Payloads are metadata attached to vectors.

Examples:

```text
run_id
heater_voltage
experiment_date
module_name
paper_title
```

Payloads enable filtering and structured retrieval.

# Approximate Nearest Neighbor Search

Vector databases usually use:

```text
ANN
```

Approximate Nearest Neighbor search.

Reason:

exact search over millions of vectors is expensive.

ANN provides:

* high speed
* scalable retrieval
* efficient similarity search
